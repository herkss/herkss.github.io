## 서장. AI와 우리 사회

질문을 잘하려면 먼저 상대를 알아야 합니다. 이 장에서는 AI가 무엇이고, 어떻게 발전해 왔으며, 우리 사회에 어떤 기회와 문제를 가져오는지 살펴봅니다.

### 서장-1. AI의 개념

**인공지능(AI, Artificial Intelligence)** 은 사람의 지적 능력(학습, 추론, 인식, 언어 이해 등)을 컴퓨터로 구현한 기술입니다.

#### AI · 머신러닝 · 딥러닝 · 생성형 AI의 관계

```text
인공지능(AI)  ⊃  머신러닝  ⊃  딥러닝  ⊃  생성형 AI(대형 언어 모델 등)
```

| 용어 | 뜻 | 예시 |
| --- | --- | --- |
| 인공지능 | 사람처럼 판단·행동하게 만드는 기술 전체 | 규칙 기반 챗봇, 바둑 AI |
| 머신러닝 | 사람이 규칙을 정하지 않고, 데이터에서 규칙을 스스로 배우는 방법 | 스팸 메일 분류 |
| 딥러닝 | 사람의 신경망을 본뜬 여러 층의 인공신경망으로 배우는 머신러닝 | 얼굴 인식, 음성 인식 |
| 생성형 AI | 학습한 패턴으로 글·그림·음성·코드를 새로 만들어 내는 AI | 대화형 AI, 이미지 생성 AI |
| 대형 언어 모델(LLM) | 아주 많은 글을 학습해 다음에 올 말을 예측하는 생성형 AI | Claude, ChatGPT, Gemini |


LLM은 Large Language Model, 우리말로 '대형 언어 모델'입니다. 아주 많은 글을 학습해서, 앞에 나온 말을 보고 다음에 올 말(토큰)을 확률로 예측하며 문장을 만들어 내는 AI입니다.

이름의 세 부분은 이런 뜻입니다.

Large(대형): 학습한 글의 양과 모델 크기(매개변수 수)가 매우 큽니다.
Language(언어): 사람의 말과 글을 이해하고 만들어 냅니다.
Model(모델): 학습으로 만들어진 계산 구조입니다. 2017년에 발표된 트랜스포머 구조를 바탕으로 합니다.



#### 약한 AI와 강한 AI

- **약한 AI(좁은 AI)**: 번역, 이미지 인식처럼 정해진 일을 잘하는 AI입니다. 지금 쓰는 AI는 모두 여기에 속합니다.
- **강한 AI(범용 인공지능, AGI)**: 사람처럼 어떤 분야든 스스로 배우고 판단하는 AI입니다. 아직 실현되지 않았고, 언제 가능할지는 전문가마다 의견이 다릅니다.

### 서장-2. AI의 발전 과정

| 시기 | 사건 | 의미 |
| --- | --- | --- |
| 1950 | 앨런 튜링, '튜링 테스트' 제안 | "기계가 생각할 수 있는가?"라는 질문의 시작 |
| 1956 | 다트머스 회의에서 '인공지능' 용어 등장 | AI가 학문 분야로 출발 |
| 1970년대 | 제1차 AI 겨울 | 기대만큼 성과가 나오지 않아 투자 감소 |
| 1980년대 | 전문가 시스템 유행 | 전문가의 규칙을 컴퓨터에 입력하는 방식 |
| 1980년대 말~1990년대 초 | 제2차 AI 겨울 | 규칙 입력 방식의 한계 드러남 |
| 1997 | IBM 딥블루, 체스 세계 챔피언에게 승리 | 계산 능력으로 사람을 이긴 상징적 사건 |
| 2012 | 딥러닝 이미지 인식(AlexNet)의 큰 성과 | 딥러닝 시대 본격 개막 |
| 2016 | 알파고, 이세돌 9단에게 승리 | 한국 사회에 AI를 널리 알린 사건 |
| 2017 | 트랜스포머(Transformer) 구조 발표 | 지금의 대형 언어 모델의 기반 기술 |
| 2022.11 | ChatGPT 공개 | 누구나 대화로 AI를 쓰는 생성형 AI 대중화 |
| 2023~2024 | 멀티모달 AI 확산 | 글뿐 아니라 이미지·음성·영상을 함께 이해하고 생성 |
| 2025~현재 | AI 에이전트 확산, AI 법제화 | AI가 여러 단계의 일을 스스로 수행하고, 각국이 AI 법을 시행 |

**핵심 정리**: AI는 "규칙을 사람이 입력하는 방식"에서 "데이터에서 스스로 배우는 방식"으로 바뀌었습니다. 지금은 "말로 지시하면 일을 해 주는 방식"으로 발전하고 있습니다. 그래서 **질문(지시)하는 능력**이 중요해졌습니다.

### 서장-3. AI와 인류의 관계

#### 도구에서 협업 파트너로

| 관계 단계 | 설명 | 예시 |
| --- | --- | --- |
| 도구 | 사람이 시키는 일을 그대로 수행 | 계산기, 번역기 |
| 조수 | 사람의 일을 돕고 초안을 만들어 줌 | 보고서 초안, 메일 작성 |
| 협업 파트너 | 사람과 의견을 주고받으며 함께 문제를 푼다 | 기획 회의, 코드 리뷰 |
| 대리인(에이전트) | 사람이 목표를 주면 여러 단계를 스스로 수행 | 자료 조사 후 보고서 작성까지 |

#### 일자리의 변화

- **줄어드는 일**: 반복적인 문서 작업, 단순 자료 입력, 정형화된 상담
- **바뀌는 일**: 디자이너, 개발자, 기자, 사무직처럼 AI를 도구로 쓰면서 일하는 방식이 달라지는 직업
- **늘어나는 일**: AI를 활용해 업무를 설계하는 일, AI 결과를 검증하는 일, AI 윤리·안전 관리

#### AI 시대에 사람이 맡아야 할 역할

1. **문제를 정의하는 사람**: 무엇을 풀어야 하는지는 사람이 정합니다.
2. **판단하고 책임지는 사람**: AI의 답을 쓸지 말지, 최종 결정과 책임은 사람에게 있습니다.
3. **가치를 지키는 사람**: 공정함, 배려, 윤리 같은 기준은 사람이 세웁니다.
4. **질문하는 사람**: 좋은 질문이 좋은 답을 만듭니다. 이 교재의 목표입니다.

### 서장-4. AI 사용의 윤리적·사회적·법적 문제

#### 1) 윤리적 문제

| 문제 | 설명 | 예시 |
| --- | --- | --- |
| 편향과 차별 | 학습 데이터의 편견이 결과에 그대로 나타남 | 채용 AI가 특정 성별이나 출신을 불리하게 평가 |
| 책임 소재 | AI가 잘못했을 때 누구 책임인지 불분명 | 자율주행차 사고, 잘못된 의료 조언 |
| 설명 불가능성 | AI가 왜 그런 결론을 냈는지 알기 어려움 | 대출 거절 이유를 설명하지 못함 |
| 인간 존엄성 | 사람을 점수나 데이터로만 판단 | 감시와 행동 점수화 |
| 사고력 의존 | 스스로 생각하지 않고 AI에 맡김 | 과제를 그대로 베껴 제출 |

#### 2) 사회적 문제

| 문제 | 설명 |
| --- | --- |
| 허위정보·딥페이크 | 진짜 같은 가짜 영상·음성·기사가 퍼져 신뢰를 무너뜨림 |
| 디지털 격차 | AI를 잘 쓰는 사람과 못 쓰는 사람의 소득·기회 차이가 커짐 |
| 일자리 불안 | 일부 직무가 빠르게 자동화됨 |
| 개인정보 침해 | 대화 내용이나 사진이 학습·유출에 쓰일 위험 |
| 에너지·환경 | AI 학습과 운영에 많은 전력과 물이 들어감 |
| 정보 독점 | 소수 대기업에 기술과 데이터가 몰림 |

#### 3) 법적 문제와 제도

**① 대한민국 「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」(AI 기본법)**

- 2024년 12월 국회를 통과했고, 2025년 1월 공포 뒤 **2026년 1월 22일부터 시행**되었습니다. 국가 단위로 포괄적인 AI 기본법을 전면 시행한 첫 사례로 평가됩니다.
- **진흥과 규제를 함께 담은 법**입니다. AI 연구개발, 데이터센터, 전문 인력 지원과 함께 신뢰 확보 의무를 규정합니다.
- **고영향 AI**: 국민의 생명·안전·기본권에 큰 영향을 주는 AI입니다. 사업자에게 안전성·신뢰성 확보 조치를 요구합니다.
- **생성형 AI 표시 의무**: AI가 만든 결과물이라는 사실을 알려야 합니다. 특히 실제와 구분하기 어려운 딥페이크 결과물은 이용자가 분명히 알아볼 수 있게 표시해야 합니다.
- **제재**: 위반하면 시정명령과 최대 3,000만 원의 과태료를 받을 수 있습니다. 다만 정부는 시행 초기 1년 이상 과태료를 부과하지 않는 **계도기간**을 운영하고 있습니다.
- 의무를 지는 쪽은 주로 **AI 사업자**입니다. 하지만 일반 사용자도 AI 생성물을 사실처럼 퍼뜨리면 다른 법(명예훼손, 저작권 등)의 책임을 질 수 있습니다.

**② 유럽연합 AI법(EU AI Act)**

- 2024년 제정된, AI를 **위험 수준별로 나누어** 규제하는 법입니다.
- **금지 AI**(사회적 점수 매기기 등)는 이미 금지되었습니다. **범용 AI(GPAI) 모델 의무**는 2025년 8월 2일부터 적용되고 있습니다.
- **투명성 의무**(챗봇임을 알리기, AI 생성물 표시)는 2026년 8월 2일부터 적용되었습니다.
- **고위험 AI 의무**(채용, 신용평가, 교육, 법 집행 등)는 2026년 7월 발효된 개정안(Digital Omnibus on AI)으로 미뤄졌습니다. 독립형 고위험 AI는 **2027년 12월 2일**, 제품에 들어간 고위험 AI는 **2028년 8월 2일**부터 적용됩니다.

**③ 그 밖의 법적 쟁점**

- **저작권**: AI가 학습에 쓴 자료의 저작권 문제, AI 생성물을 저작물로 인정할지의 문제 (제5영역에서 자세히 다룸)
- **개인정보 보호법**: AI에 넣는 개인정보, AI가 학습한 개인정보 처리 문제
- **명예훼손·초상권**: 딥페이크, 허위 사실이 담긴 AI 생성물을 퍼뜨린 경우

### 서장-5. AI가 우리 사회에 미치는 영향

6. AI 결과물을 쓴 **최종 책임은 나에게 있다**는 것을 기억한다.
7. 편향되거나 차별적인 결과가 나오면 **그대로 쓰지 않고 바로잡는다**.

## 제1영역. AI 작동 원리와 한계의 이해 (기초 이론)

AI는 "정답을 아는 존재"가 아니라 **"그럴듯한 다음 말을 확률로 고르는 기계"** 입니다. 이 사실을 알면 왜 질문을 잘해야 하는지, 왜 답을 검증해야 하는지 이해할 수 있습니다.

### 1-1. 토큰(Token)과 확률적 생성 원리

#### 토큰이란?

AI는 글을 글자나 단어가 아니라 **토큰**이라는 조각 단위로 읽고 씁니다.

```text
"나는 학교에 간다"  →  [나] [는] [ 학교] [에] [ 간] [다]   (예시, 실제 분할 방식은 모델마다 다름)
```

- 토큰은 단어 하나일 수도, 단어의 일부일 수도 있습니다.
- 한국어는 같은 내용이라도 영어보다 토큰이 더 많이 드는 경우가 많습니다.
- AI가 한 번에 읽고 쓸 수 있는 양, 그리고 사용 요금은 모두 **토큰 수**로 계산됩니다.

#### 확률적 생성 원리

AI는 앞의 토큰들을 보고 **다음에 올 토큰을 확률로 예측**하며 한 조각씩 글을 이어 씁니다.

```text
입력: "대한민국의 수도는"
다음 토큰 후보: " 서울" (매우 높음) / " 부산" (낮음) / " 어디" (낮음) ...
→ 가장 그럴듯한 " 서울"을 고르고, 다시 다음 토큰을 예측
```

**이 원리에서 나오는 세 가지 사실**

| 사실 | 질문하는 사람에게 주는 교훈 |
| --- | --- |
| AI는 "그럴듯한" 말을 고른다. "참인" 말이 아니다. | 중요한 사실은 반드시 확인해야 한다. |
| 같은 질문에도 답이 조금씩 달라질 수 있다. | 여러 번 물어 비교하면 더 좋은 답을 고를 수 있다. |
| 정보가 적으면 "가장 흔한 답"으로 빈칸을 채운다. | 맥락과 조건을 자세히 줄수록 내 상황에 맞는 답이 나온다. |

### 1-2. 컨텍스트 윈도우(Context Window)와 기억의 한계

#### 컨텍스트 윈도우란?

AI가 **한 번에 볼 수 있는 글의 최대 양**(토큰 수)입니다. 대화 내용, 첨부한 문서, AI의 답변이 모두 이 안에 들어갑니다.

- 사람으로 치면 "책상 위에 펼쳐 놓을 수 있는 종이의 양"입니다.
- 이 범위를 넘으면 앞부분 내용이 잘리거나 요약되어 **잊어버립니다**.
- AI는 대화가 끝나면 원칙적으로 내용을 기억하지 않습니다. 단, 기억 기능을 따로 켠 서비스는 예외입니다.

#### Lost in the Middle(중간 망각) 현상

긴 글을 주면 AI는 **앞부분과 뒷부분은 잘 활용하지만 가운데 내용은 놓치기 쉽습니다.** 2023년 발표된 연구에서 확인된 현상입니다.

```text
[긴 문서]  앞부분 ★★★ 잘 기억  |  가운데 ★ 놓치기 쉬움  |  뒷부분 ★★★ 잘 기억
```

**대처법**

1. 가장 중요한 지시는 **맨 앞이나 맨 뒤**에 둡니다.
2. 긴 자료는 필요한 부분만 **잘라서** 줍니다.
3. 대화가 길어지면 지금까지 정한 내용을 **요약해서 새 대화**로 옮깁니다.
4. "3페이지의 표를 기준으로"처럼 **어디를 보라고 위치를 짚어** 줍니다.

### 1-3. 할루시네이션(환각)과 편향성, 사실 검증(Grounding)

#### 할루시네이션(Hallucination, 환각)

AI가 **사실이 아닌 내용을 사실처럼 자신 있게 말하는 현상**입니다.

| 발생 원인 | 예시 |
| --- | --- |
| 그럴듯한 말을 고르는 원리 자체 | 존재하지 않는 논문, 책, 판례를 지어냄 |
| 학습 데이터에 없는 최신 정보 | 학습 이후 바뀐 법, 가격, 인물 정보를 옛날 기준으로 답함 |
| 질문이 잘못된 전제를 담음 | "세종대왕이 만든 거북선의 크기는?" → 틀린 전제에 맞춰 답을 지어냄 |
| 정확한 숫자·고유명사 | 날짜, 통계, 주소, 전화번호를 틀리게 말함 |

#### 편향성(Bias)

학습 데이터에 담긴 사회의 편견이 답에 나타나는 현상입니다.

- 직업과 성별을 고정관념으로 연결 (예: 간호사는 여성, 엔지니어는 남성)
- 특정 지역·국가·문화 중심의 시각
- 영어권 자료가 많아 한국 실정과 맞지 않는 답

#### 사실 검증(Grounding) 기준

**그라운딩**이란 AI의 답을 **확인 가능한 근거에 붙들어 매는 것**입니다.

| 방법 | 프롬프트 예시 |
| --- | --- |
| 근거 자료를 직접 주기 | "아래 붙인 공고문 내용만 근거로 답해줘." |
| 출처를 요구하기 | "답마다 출처(기관명, 문서명)를 함께 적어줘." |
| 모르면 모른다고 하게 하기 | "확실하지 않으면 추측하지 말고 '확인 필요'라고 표시해줘." |
| 검색 기능 쓰기 | 웹 검색이 되는 AI에서 "최신 자료를 검색해서" 요청 |
| 원문 확인하기 | AI가 준 출처를 사람이 직접 열어 확인 |

**검증이 꼭 필요한 정보**: 숫자·날짜·통계, 법률·의료·금융 정보, 인용문, 사람·기관 정보, 최신 뉴스

## 제2영역. 문제 정의와 사고의 구조화 (메타인지 훈련)

AI의 답 품질은 AI의 성능보다 **질문에 담긴 생각의 선명도**에 더 크게 좌우됩니다. 이 영역에서는 질문하기 전에 **생각을 정리하는 법**을 배웁니다.

### 2-1. 왜 질문이 답을 결정하는가

#### Garbage In, Garbage Out

| 구분 | 질문 | 얻게 되는 답 |
| --- | --- | --- |
| 저급한 질문 | "주식 투자 어떻게 해야 돼?" | 교과서적인 개론, 모호한 일반론 |
| 고급한 질문 | "너는 15년 차 재무 상담가야. 30대 직장인이 ISA 계좌와 연금저축펀드로 배당 성장 ETF와 미국 지수형 ETF를 7:3으로 적립할 때의 세제 혜택과 리스크 시나리오 2가지를 표로 비교해줘." | 상황에 맞게 바로 쓸 수 있는 분석 |

#### 질문은 생각의 거울이다

- **메타인지**: 내가 무엇을 알고 무엇을 모르는지 아는 능력
- **구조화**: 머릿속 생각을 순서와 항목으로 정리해 전달하는 능력

질문 연습은 AI 사용법이기 전에 **생각 정리 훈련**입니다.

#### Level 1 질문이 괜찮은 경우

답이 하나로 정해진 사실 질문에는 Level 1로도 충분합니다.

| 충분한 경우 | 부족한 경우 |
| --- | --- |
| "1인치는 몇 cm?" | "여행지 추천해줘" |
| "HTTP 404 뜻은?" | "보고서 써줘" |

**판단 기준**: 사람마다 정답이 달라질 수 있는 질문이라면 Level 1로는 부족합니다.

### 2-2. 목표 분해(Task Decomposition)

크고 모호한 요청을 한 번에 시키면 AI는 얕고 뭉뚱그린 답을 냅니다. **작은 과업(Sub-task)으로 쪼개서** 하나씩 시키면 품질이 크게 오릅니다.

#### 쪼개는 방법: "무엇을 → 어떤 순서로 → 무엇이 나와야 하나"

**예시: "가게 홍보 좀 해줘"**

```text
큰 목표: 동네 빵집 매출 올리기 위한 홍보
 ├─ 1단계: 우리 가게 강점 3가지 정리 (재료, 가격, 위치)
 ├─ 2단계: 주요 고객층 정하기 (근처 직장인, 아이 있는 가정)
 ├─ 3단계: 고객층별 홍보 문구 각 3개 만들기
 ├─ 4단계: 인스타그램 게시글 1주일 치 일정표 만들기
 └─ 5단계: 매장 앞 입간판 문구 1개 만들기
```

**쪼개기 점검 질문**

- 이 과업은 AI가 한 번의 답으로 끝낼 수 있는 크기인가?
- 앞 단계의 결과가 다음 단계의 재료가 되는가?
- 각 단계에서 내가 확인하고 고칠 기회가 있는가?

### 2-3. 핵심 요소 추출: R-C-O-F 프레임워크

좋은 질문의 네 가지 뼈대입니다.

| 요소 | 뜻 | 스스로 던질 질문 | 예시 |
| --- | --- | --- | --- |
| **R**ole (역할) | AI가 누구의 시선으로 답할지 | 어떤 전문가에게 묻고 싶은가? | "너는 초등학교 5학년 과학 교사야." |
| **C**ontext (맥락) | 나의 상황과 배경 | 누가, 언제, 어디서, 왜 필요한가? | "아이가 숙제로 광합성을 공부 중이야." |
| **O**bjective (목표) | 결국 얻고 싶은 결과물 | 무엇을 받으면 끝인가? | "광합성을 쉽게 설명해줘." |
| **F**ormat (출력 형식) | 결과물의 모양 | 표? 목록? 몇 줄? | "요리에 비유해서 5줄로, 끝에 OX 퀴즈 3문제." |

#### 맥락(C)을 채우는 5W1H

| 항목 | 점검 질문 | 맛집 예시 |
| --- | --- | --- |
| 누가 | 누구를 위한 것인가? | 초등학생 아이 둘과 부부 |
| 언제 | 시기·기한은? | 이번 토요일 점심 |
| 어디서 | 장소·환경은? | 전주 한옥마을 근처 |
| 무엇을 | 원하는 결과물은? | 한식당 3곳 |
| 어떻게 | 지켜야 할 조건은? | 주차 가능, 1인 2만 원 이하 |
| 왜 | 목적은? | 아이들에게 전통 음식 체험 |

#### 역할(R)의 효과

| 역할 | 답변이 이렇게 바뀝니다 |
| --- | --- |
| 초등학교 교사 | 쉬운 말, 비유, 짧은 문장 |
| 15년 차 현장 전문가 | 실무 용어, 현장 주의사항, 경험 기반 팁 |
| 까다로운 심사위원 | 약점과 빈틈을 먼저 짚음 |
| 면접관 | 예상 질문과 평가 기준 제시 |

#### 형식(F)의 종류

| 형식 | 언제 쓰나 | 지시 예시 |
| --- | --- | --- |
| 표 | 여러 항목을 비교할 때 | "장단점을 표로 비교해줘" |
| 체크리스트 | 빠짐없이 점검할 때 | "공정별 체크리스트로 만들어줘" |
| 번호 목록 | 순서가 중요할 때 | "단계별로 번호를 붙여줘" |
| 요약 | 시간이 없을 때 | "핵심만 3줄로" |
| 템플릿 | 반복해 쓸 때 | "빈칸을 [ ]로 표시한 양식으로" |

#### Before / After: Level 1 → Level 2 → Level 3

| 단계 | 질문 |
| --- | --- |
| Level 1 | "맛집 추천해줘" |
| Level 2 (+맥락·조건) | "전주에서 아이들과 가기 좋은 한식당 추천해줘. 주차 공간이 있어야 해." |
| Level 3 (+역할·형식) | "너는 전주 토박이 여행 가이드야. 이번 토요일 점심에 초등학생 아이 둘과 갈 한옥마을 근처 한식당 3곳을 추천해줘. 주차 가능, 1인 2만 원 이하여야 해. 가게 이름, 대표 메뉴, 아이에게 좋은 점을 표로 정리해줘." |

### 2-4. 제약 조건(Constraints)과 부정 명령(Negative Prompting)

#### 좋은 제약 조건의 4원칙

1. **구체적으로**: "짧게" → "3줄로", "싸게" → "2만 원 이하"
2. **필수와 선호를 구분**: "반드시 주차 가능, 가능하면 좌식"
3. **서로 부딪히지 않게**: "아주 자세히, 하지만 한 줄로"는 AI를 혼란에 빠뜨립니다.
4. **우선순위를 정하기**: 조건이 많으면 "가장 중요한 것은 예산"처럼 순위를 줍니다.

#### 부정 명령: "하지 말 것"을 알려주기

| 목적 | 부정 명령 예시 |
| --- | --- |
| 원하지 않는 내용 빼기 | "매운 음식은 빼줘." |
| 말투 통제 | "전문 용어와 영어 약어는 쓰지 마." |
| 군더더기 줄이기 | "인사말과 서론 없이 바로 본론부터." |
| 추측 막기 | "모르는 내용은 지어내지 마." |

**주의**: 부정 명령만 쓰면 AI가 무엇을 해야 할지 모릅니다. **"하지 말 것 + 대신 할 것"** 을 함께 쓰세요.

```text
✗ "어려운 말 쓰지 마."
○ "어려운 말 대신 초등학생이 아는 단어로 써줘."
```

### ✎ 제2영역 연습문제

1. "노트북 추천해줘"에서 빠진 R-C-O-F 요소를 모두 찾으시오.
2. "결혼식 준비 도와줘"를 5단계 이하의 작은 과업으로 분해하시오.
3. 다음 조건을 구체적으로 바꾸시오: "적당히 짧게", "싸고 좋은 걸로", "늦지 않게"
4. 다음 질문에서 서로 부딪히는 조건을 찾으시오: "초등학생도 이해할 수 있게, 전문 용어를 최대한 많이 써서 설명해줘."
5. "운동 루틴 짜줘"를 R-C-O-F 네 요소와 부정 명령 1개를 모두 넣어 다시 쓰시오.

## 제3영역. 실전 프롬프팅 기법 (핵심 스킬)

질문의 뼈대(R-C-O-F)를 세웠다면, 이제 답의 품질을 한 단계 더 끌어올리는 **세 가지 기본 기법**을 배웁니다.

### 3-1. 제로샷(Zero-shot) vs 퓨샷(Few-shot)

| 구분 | 뜻 | 언제 쓰나 |
| --- | --- | --- |
| 제로샷 | 예시 없이 지시만 주기 | 일반적인 작업, 형식이 자유로운 작업 |
| 원샷 | 예시 1개를 주기 | 원하는 형식을 간단히 보여줄 때 |
| 퓨샷 | 예시 2~5개를 주기 | 말투·형식·분류 기준을 정확히 맞추고 싶을 때 |

#### 제로샷 예시

```text
다음 고객 후기가 긍정인지 부정인지 분류해줘.
후기: "배송이 생각보다 빨랐어요."
```

#### 퓨샷 예시

```text
고객 후기를 아래 예시처럼 분류하고 이유를 한 줄로 써줘.

후기: "포장이 꼼꼼했어요." → 긍정 / 이유: 포장 만족
후기: "색이 사진과 달라요." → 부정 / 이유: 상품 불일치
후기: "가격은 비싸지만 품질은 좋아요." → 중립 / 이유: 가격 불만, 품질 만족

후기: "배송이 생각보다 빨랐어요." →
```

**퓨샷 사용 요령**

1. 예시는 **서로 다른 경우**를 골고루 보여줍니다(긍정·부정·중립).
2. 예시의 **형식을 똑같이** 맞춥니다. AI는 형식을 그대로 따라 합니다.
3. 예시에 실수가 있으면 AI도 그 실수를 따라 합니다. 예시는 꼼꼼히 확인하세요.

### 3-2. 생각의 사슬(Chain of Thought, CoT) 유도

계산, 추론, 판단이 필요한 문제는 AI가 **바로 답을 내게 하지 말고 단계별로 생각하게** 하면 정확도가 오릅니다.

#### 기본형: 한 문장 추가

```text
✗ "사과 3상자에 각 24개, 그중 15%가 상했어. 성한 사과는 몇 개야?"
○ "사과 3상자에 각 24개, 그중 15%가 상했어. 성한 사과는 몇 개야?
   단계별로 계산 과정을 보여준 뒤 마지막에 답을 써줘."
```

#### 응용형: 생각의 단계를 직접 정해 주기

```text
우리 팀 회식 장소를 정하려고 해. 다음 순서로 생각해줘.
1단계: 조건 정리 (인원 12명, 예산 1인 3만 원, 회사에서 도보 10분)
2단계: 조건에 맞는 음식 종류 후보 3가지
3단계: 각 후보의 장단점 비교
4단계: 최종 추천 1가지와 이유
```

**CoT가 효과적인 경우**: 계산, 논리 퍼즐, 여러 조건을 따지는 선택, 원인 분석, 계획 세우기
**CoT가 필요 없는 경우**: 단순 사실 질문, 번역, 짧은 문장 다듬기

> 참고: 최근에는 스스로 단계별 추론을 하도록 만들어진 '추론 특화 모델'도 있습니다. 이런 모델은 "단계별로 생각해"라고 하지 않아도 내부에서 추론합니다. 이때는 **생각의 단계를 정해 주는 응용형**이 더 효과적입니다.

### 3-3. 구조화 마크업: 지시문과 데이터 분리

긴 자료를 붙여 넣으면 AI는 **어디까지가 지시이고 어디부터가 자료인지** 헷갈릴 수 있습니다. 구분자로 경계를 분명히 나눕니다.

#### 방법 1: 마크다운 구분자

```markdown
## 지시
아래 회의록을 읽고 결정 사항과 할 일을 표로 정리해줘.

## 회의록
"""
(회의록 내용 붙여넣기)
"""

## 출력 형식
| 구분 | 내용 | 담당자 | 기한 |
```

#### 방법 2: XML 태그

```xml
<지시>
아래 고객 문의에 정중한 답장을 써줘. 환불 규정을 근거로 답해줘.
</지시>

<환불규정>
구매 후 7일 이내, 미개봉 상품에 한해 전액 환불
</환불규정>

<고객문의>
5일 전에 샀는데 포장만 뜯었어요. 환불되나요?
</고객문의>
```

**구분자를 쓰면 좋은 점**

| 효과 | 설명 |
| --- | --- |
| 혼동 방지 | 자료 안에 "~해줘"라는 문장이 있어도 지시로 착각하지 않음 |
| 위치 지정 | "<환불규정> 내용만 근거로"처럼 정확히 가리킬 수 있음 |
| 재사용 | 지시는 두고 자료만 바꿔 반복해서 쓸 수 있음 |
| 보안 | 외부에서 가져온 글에 숨은 이상한 지시를 데이터로만 다루게 함 |

### ✎ 제3영역 연습문제

1. 제로샷과 퓨샷의 차이를 한 문장으로 설명하시오.
2. 매장 SNS 글을 우리 가게 말투로 쓰게 하려고 한다. 퓨샷 예시 2개를 넣은 프롬프트를 쓰시오.
3. 다음 중 CoT가 가장 효과적인 질문은?
   - (가) "'감사합니다'를 일본어로?"
   - (나) "월급 280만 원에서 월세 55만 원, 식비 60만 원, 교통비 12만 원을 빼고, 남은 돈의 30%를 저축하면 1년에 얼마야?"
   - (다) "오늘 날씨 어때?"
   - (라) "이 문장 맞춤법 고쳐줘."
4. 이메일 원문과 요약 지시를 XML 태그로 나누어 프롬프트를 쓰시오.
5. 자료와 지시를 구분하지 않았을 때 생길 수 있는 문제를 1가지 쓰시오.

## 제4영역. 비판적 검증과 반복 개선 (멀티턴 티키타카)

AI와의 대화는 **한 번 묻고 끝내는 것이 아니라, 주고받으며 다듬는 과정**입니다. 첫 답은 초안일 뿐입니다.

### 4-1. 자기 비평 유도(Self-Critique)

AI에게 **자기가 쓴 답의 허점을 스스로 찾게** 하는 반문 기법입니다.

#### 기본 흐름

```text
1차 질문 → AI 초안
2차 질문: "방금 답에서 틀렸거나 빠졌거나 근거가 약한 부분 3가지를 찾아줘."
3차 질문: "찾은 문제를 고쳐서 최종본을 다시 써줘."
```

#### 자기 비평 질문 모음

| 목적 | 질문 예시 |
| --- | --- |
| 논리 점검 | "이 주장의 논리적 허점은 무엇이야?" |
| 반대 관점 | "이 계획에 반대하는 사람이라면 뭐라고 비판할까?" |
| 누락 점검 | "내가 고려하지 못한 위험이나 예외 상황은?" |
| 사실 점검 | "이 답에서 사실 확인이 필요한 문장을 표시해줘." |
| 기준 점검 | "처음에 준 조건 5가지를 모두 지켰는지 하나씩 확인해줘." |

### 4-2. 역질문 유도(Flipped Interaction)

내가 무엇을 알려줘야 할지 모를 때, **AI가 나에게 필요한 정보를 먼저 묻게** 하는 기법입니다.

```text
"나에게 맞는 노트북을 추천받고 싶어.
추천하기 전에 필요한 정보를 한 번에 하나씩 질문해줘.
충분한 정보가 모이면 그때 추천 3개를 표로 보여줘."
```

**효과**

- 내가 미처 생각하지 못한 조건(용도, 무게, 배터리, 예산 등)을 AI가 알려줍니다.
- 질문에 답하다 보면 **내 생각이 저절로 정리**됩니다. 메타인지 훈련이 됩니다.
- 처음부터 완벽한 질문을 쓰지 못해도 좋은 결과에 도달할 수 있습니다.

**요령**: "한 번에 하나씩" 또는 "최대 5개까지"처럼 질문 방식을 정해 주면 대화가 깔끔해집니다.

### 4-3. 팩트체크 및 다른 모델로 교차 검증

#### 팩트체크 3단계

1. **표시하기**: "이 답에서 숫자, 날짜, 고유명사, 인용문을 모두 굵게 표시해줘."
2. **출처 받기**: "각 내용의 출처를 알려줘."
3. **직접 확인하기**: 공식 기관 누리집, 원문 문서, 신뢰할 수 있는 언론에서 사람이 직접 확인합니다.

#### 교차 검증

| 방법 | 설명 |
| --- | --- |
| 다른 AI에 같은 질문 | Claude, ChatGPT, Gemini 등에 같은 질문을 하고 답을 비교 |
| 다른 AI에 검토 맡기기 | A AI의 답을 B AI에 주고 "틀린 부분을 찾아줘" |
| 질문을 바꿔 다시 묻기 | 같은 내용을 다른 표현으로 물어 답이 일관된지 확인 |
| 검색 결과와 비교 | AI 답과 검색 결과를 나란히 놓고 비교 |

**판단 기준**: 여러 AI의 답이 일치해도 **모두 같은 실수를 할 수 있습니다.** 중요한 정보의 최종 확인은 원문과 공식 자료로 합니다.

### 4-4. 반복 개선의 기본 순서

```text
① 질문(R-C-O-F) → ② 초안 받기 → ③ 자기 비평 → ④ 팩트체크 → ⑤ 수정 요청 → ⑥ 최종 확인(사람)
```

**수정 요청을 잘하는 법**

| ✗ 막연한 수정 요청 | ○ 구체적인 수정 요청 |
| --- | --- |
| "다시 써줘." | "두 번째 문단을 반으로 줄이고, 예시를 하나 추가해줘." |
| "별로야." | "말투가 너무 딱딱해. 친한 선배가 말하듯 바꿔줘." |
| "더 좋게." | "결론을 맨 앞으로 옮기고, 숫자 근거를 넣어줘." |

### ✎ 제4영역 연습문제

1. AI가 쓴 사업 계획 초안의 허점을 찾게 하는 자기 비평 질문을 2개 쓰시오.
2. 이사할 동네를 추천받으려 한다. 역질문 유도 프롬프트를 쓰시오.
3. 세 AI가 똑같은 통계 숫자를 답했다. 그래도 원문을 확인해야 하는 이유는?
4. "다시 써줘"를 구체적인 수정 요청으로 바꾸시오(대상: 자기소개서).
5. 반복 개선의 기본 순서 6단계를 쓰시오.

## 제5영역. 윤리, 보안 및 모델 선택 전략 (실무 응용)

AI를 잘 쓰는 사람은 **안전하게** 쓰는 사람입니다. 그리고 **목적에 맞는 도구를 고를 줄 아는** 사람입니다.

### 5-1. 데이터 프라이버시, 기업 기밀, 개인정보 비식별화

#### 넣으면 안 되는 정보

| 구분 | 예시 |
| --- | --- |
| 개인 식별 정보 | 주민등록번호, 여권번호, 운전면허번호 |
| 금융 정보 | 계좌번호, 카드번호, 비밀번호 |
| 민감 정보 | 건강 기록, 진료 내용 |
| 회사 기밀 | 미공개 재무 자료, 고객 명단, 계약서 원본, 소스 코드 핵심부 |
| 타인 정보 | 동의 없는 다른 사람의 이름·연락처·사진 |

> 서비스와 요금제에 따라 대화 내용이 AI 학습에 쓰일 수 있습니다. 회사에서는 **회사가 허용한 AI 도구와 사용 지침**을 먼저 확인하세요.

#### 비식별화 처리 기준

| 방법 | 원본 | 처리 후 |
| --- | --- | --- |
| 가명 처리 | 홍길동 고객 | 고객 A |
| 삭제 | 010-1234-5678 | (삭제) |
| 범주화 | 37세 | 30대 |
| 일반화 | 서울시 강남구 테헤란로 123 | 서울 |
| 대체 | ㈜한빛전자 | 거래처 B사 |

**연습 예시**

```text
✗ "김철수(010-1234-5678, 서울 마포구 ○○아파트) 고객이 환불을 요구하는데 답장 써줘."
○ "고객 A가 구매 5일 후 환불을 요구해. 정중한 거절 답장을 써줘."
```

### 5-2. AI 생성물의 저작권 이슈와 인간의 최종 책임

#### 저작권의 기본 원칙

1. **AI가 혼자 만든 결과물은 원칙적으로 저작물로 보호받기 어렵습니다.** 한국과 미국 모두 저작권은 사람의 창작에 주어진다는 입장입니다. 사람이 고르고, 배치하고, 고친 **창작적 기여 부분**은 보호받을 수 있습니다.
2. **AI 결과물이 다른 사람의 작품과 비슷하면 저작권 침해가 될 수 있습니다.** 유명 캐릭터, 노래 가사, 특정 작가의 그림체를 흉내 낸 결과물은 특히 주의해야 합니다.
3. **AI에 넣는 자료도 저작권이 있습니다.** 남의 책이나 기사를 통째로 넣어 재가공해 배포하면 문제가 될 수 있습니다.
4. **서비스 약관을 확인합니다.** AI 서비스마다 결과물의 상업적 이용 조건이 다릅니다.

#### 인간의 최종 책임 범위

| 상황 | 책임지는 사람 |
| --- | --- |
| AI가 쓴 보고서에 틀린 숫자 | 보고서를 제출한 사람 |
| AI가 만든 이미지가 타인 저작물과 유사 | 그 이미지를 게시·판매한 사람 |
| AI가 쓴 글에 명예훼손 내용 | 그 글을 퍼뜨린 사람 |
| AI 코드의 보안 결함 | 그 코드를 배포한 개발자·회사 |

**핵심**: "AI가 그랬어요"는 변명이 되지 않습니다. **AI는 초안을 만들고, 책임은 사람이 집니다.**

#### AI 활용 사실 밝히기

- 학교 과제, 공모전, 언론 기사 등은 **AI 사용 규정**을 먼저 확인합니다.
- 필요하면 "이 글은 AI의 도움을 받아 작성했습니다"처럼 밝힙니다.
- 한국 AI 기본법과 EU AI법은 사업자에게 AI 생성물 표시 의무를 두고 있습니다(서장-4 참고).

### 5-3. 과업 목적에 따른 AI 모델 선택 및 조합 전략

AI 모델마다 잘하는 일이 다릅니다. 같은 회사의 모델도 **크기와 종류**에 따라 성격이 다릅니다.

#### 모델 유형별 특징

| 유형 | 잘하는 일 | 이런 과업에 |
| --- | --- | --- |
| 초장문 처리형 (긴 컨텍스트) | 아주 긴 문서를 한 번에 읽고 분석 | 계약서·논문·매뉴얼 전체 분석 |
| 추론 특화형 | 여러 단계의 논리·수학·코딩 문제 | 복잡한 계산, 원인 분석, 프로그래밍 |
| 빠른 경량형 | 짧고 빠른 답, 저렴한 비용 | 간단한 분류, 번역, 맞춤법 |
| 창의 작업형 | 글쓰기, 아이디어, 다양한 표현 | 카피라이팅, 이야기, 기획 아이디어 |
| 멀티모달형 | 이미지·음성·영상 이해 | 사진 속 표 읽기, 회의 녹음 정리 |
| 검색 연동형 | 최신 정보 반영, 출처 제시 | 최신 뉴스, 가격, 법 개정 확인 |
| 이미지·영상 생성형 | 그림, 디자인 시안, 영상 | 포스터 시안, 썸네일 |

> 모델은 빠르게 바뀝니다. 특정 모델 이름보다 **"내 과업에 필요한 능력이 무엇인가"** 를 먼저 생각하세요. 그다음 최신 비교 자료를 확인하세요.

#### 선택 기준 4가지

1. **정확도**: 틀리면 큰일 나는 일인가? → 추론형 + 검색 연동 + 교차 검증
2. **분량**: 넣을 자료가 많은가? → 초장문 처리형
3. **속도·비용**: 많이, 자주, 빨리 해야 하는가? → 경량형
4. **최신성**: 최근 정보가 필요한가? → 검색 연동형

#### 조합 전략 예시: 신제품 홍보 기획

```text
① 검색 연동형 AI  → 경쟁 제품과 시장 동향 조사 (출처 포함)
② 추론 특화형 AI  → 조사 결과로 우리 제품의 차별점 분석
③ 창의 작업형 AI  → 홍보 문구 10개 생성
④ 다른 AI        → 문구의 과장 광고 위험과 맞춤법 교차 검증
⑤ 이미지 생성형 AI → 포스터 시안
⑥ 사람           → 최종 선택, 사실 확인, 저작권 점검, 책임
```

### 6-2. 완성 예시: 실습 6

**① Level 1 원문**: "현장 안전교육 자료 만들어줘"

**② 목표 분해**

1. 교육 대상과 시간 정하기
2. 주요 위험 요소 정리
3. 교육 자료 본문 작성
4. 이해도 확인 퀴즈 작성

**③~⑤ 완성 프롬프트**

```xml
<역할>
너는 15년 차 건설 현장 안전관리자야.
</역할>

<맥락>
다음 주 월요일 아침 조회 시간에 철근 작업 신규 작업자 10명을 대상으로 15분 안전교육을 해야 해.

</맥락>

<목표>
철근 운반·조립 작업의 주요 위험과 예방법을 교육 자료로 만들어줘.
</목표>

<제약>
- 반드시 추락, 끼임, 베임, 낙하물 위험을 포함해줘.
- 법 조항 번호를 지어내지 마. 확실하지 않으면 '확인 필요'라고 표시해줘.
- 어려운 한자어 대신 현장에서 쓰는 쉬운 말로 써줘.
</제약>

<형식>
1. 위험 요소별 표 (위험 | 사고 예시 | 예방 수칙 3가지)
2. 마지막에 OX 퀴즈 5문제와 정답
</형식>

먼저 위험 요소를 정리하고, 그다음 예방 수칙을 단계별로 생각해서 작성해줘.
```

**⑥ 검증 질문**

- "방금 자료에서 신규 작업자가 오해하기 쉬운 표현을 찾아 고쳐줘."

**⑦ 보안·책임 점검**

- 최종 자료는 안전관리 책임자가 검토했는가? ✔

## 부록 A. 정답 및 해설

### 서장 연습문제

1. 인공지능 ⊃ 머신러닝 ⊃ 딥러닝 ⊃ 생성형 AI
2. 트랜스포머(Transformer)
3. (예시) 문제를 정의하는 사람: AI는 무엇을 풀지 스스로 정하지 못한다. / 판단하고 책임지는 사람: AI 결과의 최종 책임은 사람에게 있다.
4. 국민의 생명·안전·기본권에 큰 영향을 줄 수 있어 안전성·신뢰성 확보 조치가 필요한 AI
5. (예시) 가짜 정보로 사회적 신뢰가 무너진다. / 특정인의 명예와 초상권을 침해한다.

### 제1영역 연습문제

1. AI는 앞에 나온 토큰들을 보고 다음에 올 토큰을 확률로 예측하며 한 조각씩 글을 이어 쓴다.
2. AI는 확률로 다음 토큰을 고르기 때문에, 같은 질문에도 매번 조금씩 다른 선택을 할 수 있다.
3. Lost in the Middle. 대처법: 중요한 지시를 앞이나 뒤에 두기, 자료를 나눠서 넣기, 위치를 짚어 주기 등
4. (나) 최신의 구체적인 숫자 정보는 학습 데이터에 없거나 틀리기 쉽다.
5. (예시) "공신력 있는 맛집 평가 자료를 근거로, 각 순위의 출처를 함께 적어줘. 확실하지 않으면 '확인 필요'라고 표시해줘."

### 제2영역 연습문제

1. R(역할), C(맥락: 용도·예산·사용자), O(목표가 막연함: 몇 개를 어떤 기준으로?), F(형식) 모두 빠짐
2. (예시) ① 예산과 날짜 정하기 → ② 예식장 후보 비교 → ③ 하객 명단 정리 → ④ 준비물 체크리스트 → ⑤ 주차별 일정표
3. (예시) "200자 이내로", "10만 원 이하이면서 후기 평점 4.5 이상", "오후 6시까지"
4. "초등학생도 이해할 수 있게"와 "전문 용어를 최대한 많이 써서"가 서로 부딪힌다.
5. (예시) "너는 10년 차 헬스 트레이너야(R). 나는 40대 사무직이고 주 3회, 회당 40분 운동할 수 있어. 무릎이 약해(C). 4주 근력 운동 루틴을 짜줘(O). 요일별 표로, 동작·횟수·세트를 적어줘(F). 점프 동작은 넣지 말고 대신 저충격 동작으로 바꿔줘(부정 명령)."

### 제3영역 연습문제

1. 제로샷은 예시 없이 지시만 주고, 퓨샷은 예시를 여러 개 보여주고 따라 하게 한다.
2. (예시) "우리 빵집 인스타그램 글을 아래 예시 말투로 써줘. 예시1: '오늘 아침 갓 구운 소금빵, 버터 향 가득 담아 기다릴게요 🥐' 예시2: '비 오는 날엔 따뜻한 단팥빵 어때요? 3시 전 방문 시 커피 할인!' 주제: 새로 나온 무화과 깜빠뉴"
3. (나) 여러 단계의 계산이 필요하다.
4. (예시) `<지시>아래 이메일을 3줄로 요약하고 내가 할 일을 따로 적어줘.</지시><이메일>(원문)</이메일>`
5. 자료 안의 문장을 AI가 지시로 착각해 엉뚱한 작업을 할 수 있다.

### 제4영역 연습문제

1. (예시) "이 계획에서 가장 실패하기 쉬운 부분 3가지는?" / "투자자가 반대한다면 어떤 근거로 반대할까?"
2. (예시) "이사할 동네를 추천받고 싶어. 추천 전에 필요한 정보를 한 번에 하나씩, 최대 6개까지 물어봐줘. 다 답하면 후보 3곳을 표로 비교해줘."
3. 여러 AI가 같은 잘못된 자료로 학습해 같은 실수를 할 수 있기 때문이다.
4. (예시) "지원 동기 문단을 200자로 줄이고, 생산직 지원에 맞게 현장 경험 예시를 하나 넣어줘."
5. 질문 → 초안 → 자기 비평 → 팩트체크 → 수정 요청 → 사람의 최종 확인

### 제5영역 연습문제

1. (예시) "40대 환자 A의 검사 결과를 요약해줘." (이름 가명 처리, 나이 범주화, 주소 삭제)
2. (예시) 다른 작품과 비슷하지 않은지 확인, 서비스 약관의 상업적 이용 조건 확인
3. 보고서를 검토 없이 사용·제출한 사람(또는 그 회사)
4. 초장문 처리형(긴 컨텍스트) 모델
5. (예시) ① 검색 연동형으로 이번 주 환율 자료와 출처 수집 → ② 추론 특화형으로 원인 분석 → ③ 다른 AI로 교차 검증 → ④ 사람이 공식 자료와 대조

## 부록 C. 바로 쓰는 프롬프트 템플릿

### 템플릿 1. 기본형 (R-C-O-F)

```text
[역할] 너는 ________ 이야.
[맥락] 나는 ________ 상황이야. (누가 / 언제 / 어디서 / 왜)
[목표] ________ 를 만들어줘.
[제약] 반드시 ________. ________ 는 빼고 대신 ________.
[형식] ________ (표 / 체크리스트 / 번호 목록 / ○줄 요약) 형식으로.
```

### 템플릿 2. 목표 분해형

```text
[목표] ________ 를 하려고 해.
다음 순서로 하나씩 진행해줘. 각 단계가 끝나면 내 확인을 받고 다음으로 넘어가.
1단계: ________
2단계: ________
3단계: ________
```

### 템플릿 3. 퓨샷형

```text
아래 예시와 같은 형식과 말투로 ________ 해줘.
예시1: ________ → ________
예시2: ________ → ________
이번 입력: ________ →
```

### 템플릿 4. 단계적 추론(CoT)형

```text
________ 문제를 풀어줘.
1) 주어진 조건 정리 → 2) 풀이 과정 단계별 설명 → 3) 최종 답 → 4) 검산
```

### 템플릿 5. 자료 분석형 (XML)

```xml
<지시>________ 를 해줘. <자료> 안의 내용만 근거로 하고, 없는 내용은 '자료에 없음'이라고 써줘.</지시>
<자료>
(비식별화한 자료 붙여넣기)
</자료>
<형식>________</형식>
```

### 템플릿 6. 역질문 유도형

```text
________ 에 대해 도움을 받고 싶어.
가장 좋은 답을 주려면 어떤 정보가 필요한지 한 번에 하나씩, 최대 ○개까지 나에게 질문해줘.
정보가 다 모이면 ________ 형식으로 정리해줘.
```

### 템플릿 7. 자기 비평·개선형

```text
방금 답을 검토해줘.
1) 틀렸거나 근거가 약한 부분
2) 빠진 내용
3) 처음 준 조건을 어긴 부분
을 찾아 목록으로 보여준 뒤, 모두 고친 최종본을 다시 써줘.
```

## 부록 D. 용어집

| 용어 | 뜻 |
| --- | --- |
| 프롬프트(Prompt) | AI에게 주는 질문이나 지시문 |
| 프롬프트 리터러시 | AI에게 정확한 질문을 던져 원하는 결과를 얻는 능력 |
| 대형 언어 모델(LLM) | 많은 글을 학습해 다음 말을 예측하는 AI 모델 |
| 생성형 AI | 글·그림·음성·코드를 새로 만들어 내는 AI |
| 토큰(Token) | AI가 글을 읽고 쓰는 조각 단위 |
| 컨텍스트 윈도우 | AI가 한 번에 볼 수 있는 글의 최대 양 |
| Lost in the Middle | 긴 글의 가운데 내용을 AI가 놓치기 쉬운 현상 |
| 할루시네이션(환각) | AI가 사실이 아닌 내용을 사실처럼 말하는 현상 |
| 편향(Bias) | 학습 데이터의 편견이 답에 나타나는 현상 |
| 그라운딩(Grounding) | AI의 답을 확인 가능한 근거에 연결하는 것 |
| 메타인지 | 내가 무엇을 알고 모르는지 아는 능력 |
| 목표 분해 | 큰 과업을 작은 하위 과업으로 나누는 것 |
| R-C-O-F | Role(역할), Context(맥락), Objective(목표), Format(형식) |
| 페르소나 | AI에게 부여하는 역할이나 인물 설정 |
| 제약 조건 | 답이 지켜야 할 조건 |
| 부정 명령 | "하지 말 것"을 알려주는 지시 |
| 제로샷 | 예시 없이 지시만 주는 방식 |
| 퓨샷 | 예시를 여러 개 보여주고 따라 하게 하는 방식 |
| 생각의 사슬(CoT) | 단계별로 생각하게 해서 추론 정확도를 높이는 기법 |
| 구분자 | 지시와 자료를 나누는 표시 (마크다운 제목, """, XML 태그 등) |
| 자기 비평 | AI가 스스로 답의 허점을 찾게 하는 기법 |
| 역질문 유도 | AI가 사람에게 필요한 정보를 묻게 하는 기법 |
| 교차 검증 | 여러 AI나 자료로 답을 비교해 확인하는 것 |
| 멀티턴 | 여러 번 주고받는 대화 |
| 비식별화 | 개인을 알아볼 수 없게 정보를 가리거나 바꾸는 처리 |
| 딥페이크 | AI로 만든 진짜 같은 가짜 영상·음성·이미지 |
| 고영향 AI | 생명·안전·기본권에 큰 영향을 줄 수 있는 AI (한국 AI 기본법) |
| AI 에이전트 | 목표를 받으면 여러 단계를 스스로 수행하는 AI |
| 멀티모달 | 글·이미지·음성·영상을 함께 다루는 능력 |
| 범용 인공지능(AGI) | 사람처럼 모든 분야를 스스로 배우고 판단하는 AI (아직 실현되지 않음) |
